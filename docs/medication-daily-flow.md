# 长期服药与每日打卡

主流程是“今日查看本次计划 → 记录完整服用、部分服用或跳过 → 查看结果 → 必要时撤销”，药品配置集中放在“我的药品”。公共药品库是选药入口，关闭药品库功能仍可管理自己的药品。

## 业务规则

- 今日计划、历史计划与提醒使用 `ScheduleOccurrences` 的周期规则。每隔 N 天以开始日期为锚点；结束日期包含当天；所有日期边界使用提醒时区。小时制间隔在实际服用后重新起算，计划投影会重放记录中的实际时间。
- 剂量身份包含药品 ID 和具体计划时间，不能用“药品今天是否服过”代替。同一天多个时间槽、间隔给药及跨日刷新都保持独立；桌面小组件传递同一个计划时间。
- 界面收到持久化结果后才显示保存成功。操作返回修改前后的记录，撤销既能取消新增记录，也能恢复刚刚删除的记录；记录被后续操作改变时，旧撤销请求不能覆盖新记录。
- 完整与部分服用都保存实际数量。库存另外记录本次真实扣减量，因此库存不足时的截断、后续调整单次药量、之后才启用库存，都不会令撤销凭空增加库存。
- 药品计划的修改、停用、恢复与旧计划快照在同一事务中提交。库存调整不产生计划快照。修改备注时保留原有创建时间、停用状态和并发变化的库存。
- 新增与编辑共用校验；保存同步防重入，并固定点击时的草稿。首次异步读取只填充未编辑字段；恢复的编辑草稿不被再次加载覆盖。欢迎引导在用户编辑或提交后不再被 DataStore 初值覆盖。
- 近 30 天坚持率采用“完整服用次数 / 已到期计划次数”。部分服用单独显示，不使用固定 0.5 权重。未来时间槽不计入分母；按需用药保留记录但不计入计划坚持率；没有到期计划时显示中性空状态。

数据库升级到版本 18。升级前没有保存过的计划变更时间无法追溯重建；旧完整服用记录缺少数量时，以升级时可取得的剂量兼容原有撤销行为。新记录保存数量与库存扣减量，新计划变更保存历史快照。

## 界面与代码结构

- `FuturePlanCalculator` 负责把持久化配置和计划快照转换为具体剂量；`MedicationAdherenceCalculator` 负责合并计划与实际记录。首页、历史、详情与小组件复用这些规则，日志匹配先精确匹配再兼容旧时间戳。
- 历史与详情共用 `MedicationAdherenceCard`；主要用药页面共用 `MedicationMessageCard`，以及现有的主题形状、间距、顶栏和操作组件。
- 页面可见时按分钟更新时间，恢复前台时立即刷新。当天的数据订阅会被复用，跨日或切换提醒时区后才改变查询日期边界。计划与统计计算在可注入的后台计算调度器上执行。
- 列表使用可保存的稳定键和内容类型；药品列表过滤、统计汇总与日志分组避免在无关重组时重复执行。列表底部保留添加按钮所需空间。

## 验证入口

- JVM：WelcomeViewModelTest、AddMedicationViewModelTest、HomeViewModelTest、ToggleMedicationDoseUseCaseTest、MedicationAdherenceTest、ObserveMedicationAdherenceTest、ScheduleOccurrencesTest。
- Room：MedLogDatabaseMigrationTest 覆盖历史版本升级；MedicationDaoTransactionTest 验证计划与快照共同回滚、停用恢复历史及库存更新。
- Compose：MedicationFlowUiTest 使用文字和语义断言检查大字号空状态、重试操作、自己的药品与药品库入口、停用药品可达性；不读取图像。
- 常规检查：`./gradlew ktlintCheck test lintDebug assembleDebug compileDebugAndroidTestKotlin`。
- 已启动设备上的文字与迁移回归：`bash scripts/test-medication-flow.sh`。
